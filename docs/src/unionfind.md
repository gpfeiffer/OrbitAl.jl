# Union-Find

!!! note
    This is an on-demand module. Load it with `using OrbitAl.unionfind`.

Union-Find maintains an equivalence relation that grows by adding relations
one at a time, and answers whether two elements are equivalent.  It comes in
two versions, as two methods each of `find` and `unite!`:

- **Union-Find**, for an equivalence relation on `1:n` generated by pairs.  A
  forest `parent` has `parent[i] == i` for the roots; each class is a tree, and
  its root is its smallest element.
- **Linear Union-Find**, for linear relations between the basis vectors
  ``e_1, e_2, \dots``, given as [`SparseVec`](@ref OrbitAl.sparsevec.SparseVec)s.
  A dictionary `parent` maps each inactive position `i` to the vector that
  replaces ``e_i``.  `find` computes canonical forms modulo the relations.

In both versions, `unite!` returns the element that has become inactive, or
`0` if the relation adds nothing.  Union-Find is the special case of linear
Union-Find for the relations ``e_i = e_j``.

Linear Union-Find solves a relation for its last position with a **unit**
coefficient: over a field, simply its last position.  The coefficients may
also come from a ring, even a non-commutative one acting from the left, such
as a Hecke algebra.  Such a coefficient type adds a method to
[`isunit`](@ref OrbitAl.unionfind.isunit), and `unite!` returns `-1` for a
relation that has no unit coefficient.

```jldoctest
julia> using OrbitAl.unionfind, OrbitAl.sparsevec

julia> forest = collect(1:5);

julia> unite!(forest, 2, 5), unite!(forest, 5, 4), unite!(forest, 4, 2)
(5, 4, 0)

julia> find(forest, 5)
2

julia> e(i) = unitVec(Rational{Int}, i);

julia> parent = Dict{Int, SparseVec{Rational{Int}}}();

julia> unite!(parent, e(4), e(1) + e(3)), unite!(parent, e(3), 2 * e(2))
(4, 3)

julia> find(parent, e(4))
e1 + (2)e2
```

The coset enumerator in [`OrbitAl.enumerator`](@ref Coset-Enumeration) adds
methods for coset tables: Union-Find with consequences.

## Relations that have to wait

Over a ring with non-units, `unite!` can fail to solve a relation at all: it
returns `-1`, and the caller holds the relation until further reductions give
it a unit coefficient.  A set of such relations can be stuck even though
*together* they determine a position — each one has no unit of its own, while
a combination of them does.

[`echelon!`](@ref OrbitAl.unionfind.echelon!) is one fraction-free pass over
the waiting relations that brings such a unit to the surface.  It replaces
rather than appends, so the number of relations never grows.  Clearing a
position forms `p[c] * r - r[c] * p`, whose entry at that position is the
commutator of the two coefficients, so the coefficients have to commute —
[`commutes`](@ref OrbitAl.unionfind.commutes) is the test, and the caller
makes it.

```jldoctest
julia> using OrbitAl.unionfind, OrbitAl.sparsevec, OrbitAl.modn

julia> Z = Zn{12};                      # 2 and 3 are not units mod 12

julia> r1 = SparseVec([1, 2], [Z(2), Z(3)]); r2 = SparseVec([1, 2], [Z(3), Z(2)]);

julia> parent = Dict();

julia> unite!(parent, r1, zero(r1)), unite!(parent, r2, zero(r2))
(-1, -1)

julia> rels = [r1, r2]; echelon!(parent, rels)
1

julia> rels[2]                          # 2 r2 - 3 r1 = -5 e2, and -5 is a unit
(7)e2

julia> unite!(parent, rels[2], zero(rels[2]))
2
```
